**Identity is opt-in.** The SDKs never send an identifier of your own until you ask them to. Linking analytics to real user ids is a product and privacy decision, not an integration detail, so a coding agent must get an explicit yes from a human before wiring up `Pulse.setUser` / `Pulse.withUser` — and stays anonymous-only if nobody answers.

Anonymous-only is a complete setup, not a degraded one. In the browser and on Apple and Android, `Pulse.configure()` mints a persistent anonymous id (`pulse_anon_<uuid>`) and stamps it on every event, so [events](/docs/concepts/events), sessions, [metrics](/docs/concepts/metrics), [funnels](/docs/concepts/funnels), and [issue](/docs/concepts/issues) grouping all work per person without you supplying anything. What you give up is following the same person across devices and browsers, and looking one up by your own account id.

The Node.js SDK is the exception. A server has no device to anchor an anonymous id to, so events emitted from the base `Pulse` instance carry no user id at all, and a funnel — which counts distinct user ids — never sees them. The consent-free way to keep the backend attached to the rest of the picture is [`Pulse.withSession()`](/docs/sdks/node/identity#withsession): forward the client's session id as a request header and the server's events land in the same session as the browser's, with no personal identifier involved.
