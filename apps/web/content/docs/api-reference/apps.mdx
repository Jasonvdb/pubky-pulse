Create, list, get, update, and delete apps within projects.

Apps represent a specific platform build (e.g., iOS, Android, Web) within a project. Each app has its own client API key for SDK event ingestion.

## Reads and writes

Every team member can **read** every app in the team. Creating, updating or deleting an app is an ordinary project write and requires ownership of the app's **parent project**; a viewer receives `403 Requires project ownership`. Deleting an app is additionally human-only — agent keys receive `403` whatever their permissions.

`client_secret` is the app's ingestion credential and is returned only to owners of the parent project. Everyone else — the team owner included — sees `client_secret: null`. A `null` means "you may not see this", not "this app has no key". See [Authentication & Access Control](/docs/concepts/authentication).

## GET /v1/apps

List all apps the caller has access to.

**Auth required:** Yes (`apps:read` permission or JWT)

| Parameter | Type | Description |
|-----------|------|-------------|
| `team_id` | string | Optional. Filter to a specific team. |

```json
// Response (200)
{
  "apps": [
    {
      "id": "uuid",
      "team_id": "uuid",
      "project_id": "uuid",
      "name": "iOS App",
      "platform": "apple",
      "bundle_id": "com.example.myapp",
      "allowed_origins": [],
      "client_secret": "pulse_client_abc123...",
      "created_at": "2024-01-01T00:00:00.000Z"
    }
  ]
}
```

`allowed_origins` is always an array, never `null` — it is empty for every platform except `web`, and empty for a `web` app whose origins have not been set yet. See [POST /v1/apps](#post-v1apps).

Each row also carries `latest_app_version` and `latest_app_version_updated_at` — the current public release as computed from recent production events. See [Latest Version Detection](/docs/concepts/latest-version-detection).

## POST /v1/apps

Create a new app within a project. A client API key is automatically generated and returned in the `client_secret` field.

**Auth required:** Yes (`apps:write` permission or JWT) **and ownership of the parent project.**

```json
// Request
{
  "name": "iOS App",
  "platform": "apple",
  "bundle_id": "com.example.myapp",
  "project_id": "uuid"
}

// Response (201)
{
  "id": "uuid",
  "team_id": "uuid",
  "project_id": "uuid",
  "name": "iOS App",
  "platform": "apple",
  "bundle_id": "com.example.myapp",
  "allowed_origins": [],
  "client_secret": "pulse_client_full_key...",
  "created_at": "2024-01-01T00:00:00.000Z"
}
```

A web app, with its site identifier and the origins its client key may send from:

```json
// Request
{
  "name": "Acme Web",
  "platform": "web",
  "bundle_id": "app.acme.com",
  "allowed_origins": ["https://app.acme.com", "http://localhost:5173"],
  "project_id": "uuid"
}
```

### Field reference

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Display name for the app. |
| `platform` | string | Yes | One of: `apple`, `android`, `web`, `backend`. |
| `bundle_id` | string | Conditional | Required for non-backend platforms. Immutable after creation. Reverse-DNS on `apple`/`android` (`com.example.acme`), the site identifier on `web` (`app.acme.com`). |
| `allowed_origins` | string[] | No | `web` only. Browser origins this site may send from. Defaults to `[]`. |
| `project_id` | string | Yes | The project this app belongs to. Team is derived from the project. |

### Platform notes

- **Backend** apps do not require a `bundle_id` (it is set to `null`). The ingest route skips bundle_id validation for these apps.
- **bundle_id is immutable.** It cannot be changed after app creation. To change a bundle_id, delete and recreate the app.

### allowed_origins

Each entry is a full origin — scheme, host, optional port — with no path, no query string, and no trailing slash, which is exactly the shape of the `Origin` header a browser sends. `https://app.acme.com` and `http://localhost:5173` are valid; `acme.com`, `https://acme.com/`, and `https://acme.com/analytics` are not.

- **Web only.** Sending the field for an `apple`, `android`, or `backend` app returns a `400` saying the field is supported for web apps only.
- **Normalised on write.** Scheme and host are lowercased, a default port is dropped (`https://acme.com:443` → `https://acme.com`), and duplicates collapse. The stored list is what you read back.
- **Validated on write.** An entry that is not a bare `http`/`https` origin returns a `400` naming the offending value. Wildcards are not supported — list each host. Maximum 50 entries.
- **Enforced on ingest.** A request for this app carrying an `Origin` header not on the list is refused with `403`. Requests with no `Origin` (native SDKs, backends, `curl`) pass. An empty list therefore blocks every browser request.
- **Honoured by CORS.** Registered origins are allowed automatically, cached for up to a minute, so adding a site needs no server redeploy and no change to `CORS_ORIGINS`.

See [Allowed Origins](/docs/concepts/projects-and-apps#allowed-origins) for the reasoning.

## PATCH /v1/apps/:id

Update an app's `name`, its `allowed_origins`, or both. At least one is required; `platform` and `bundle_id` are immutable. Fields you omit are left alone, so renaming an app never clears its origin list.

**Auth required:** Yes (`apps:write` permission or JWT) **and ownership of the app's project.**

```json
// Request
{
  "name": "Renamed App"
}

// Response (200)
{
  "id": "uuid",
  "team_id": "uuid",
  "project_id": "uuid",
  "name": "Renamed App",
  "platform": "apple",
  "bundle_id": "com.example.myapp",
  "allowed_origins": [],
  "client_secret": "pulse_client_abc123...",
  "created_at": "2024-01-01T00:00:00.000Z"
}
```

`allowed_origins` **replaces** the whole list — send every origin you want to keep, not just the new one. It is validated exactly as on create, and an update to it is recorded in the audit log with the before and after lists.

```json
// Request — add a staging host to an existing web app
{
  "allowed_origins": [
    "https://app.acme.com",
    "https://staging.acme.com",
    "http://localhost:5173"
  ]
}
```

## DELETE /v1/apps/:id

Soft-delete an app and its associated API keys.

**Auth required:** Yes (JWT only — agent keys receive `403`) **and ownership of the app's project.**

```json
// Response (200)
{
  "deleted": true
}
```

## GET /v1/apps/:id/users

List users seen by a specific app, ordered by most recently seen.

**Auth required:** Yes (`apps:read` permission or JWT)

| Parameter | Type | Description |
|-----------|------|-------------|
| `search` | string | Filter by user_id substring (case-insensitive). |
| `is_anonymous` | string | `"true"` for anonymous users only, `"false"` for identified users only. |
| `data_mode` | string | `production` (default), `development`, or `all`. Filters on the user's `is_dev` flag. |
| `cursor` | string | Cursor from previous response. |
| `limit` | number | Items per page (1-200, default 50). |

```json
// Response (200)
{
  "users": [
    {
      "id": "uuid",
      "project_id": "uuid",
      "user_id": "pulse_anon_abc123",
      "is_anonymous": true,
      "first_seen_at": "2024-01-01T00:00:00.000Z",
      "last_seen_at": "2024-01-15T10:30:00.000Z",
      "last_country_code": "US",
      "last_app_version": "1.2.0",
      "last_sdk_name": "pubky-pulse-swift",
      "last_sdk_version": "0.1.0",
      "claimed_from": null,
      "properties": {},
      "apps": [
        {
          "app_id": "uuid",
          "app_name": "iOS App",
          "first_seen_at": "2024-01-01T00:00:00.000Z",
          "last_seen_at": "2024-01-15T10:30:00.000Z"
        }
      ]
    }
  ],
  "cursor": "2024-01-14T08:00:00.000Z",
  "has_more": false
}
```

App users are project-scoped: the `project_id` identifies the project, and the `apps` array lists each app within that project that has seen this user. A user seen from multiple apps in the same project appears once, not once per app.

`last_country_code` is a 2-letter ISO country code derived server-side from the Cloudflare `CF-IPCountry` header on the most recent ingest request that carried one. It is never sent by SDKs, and is `null` until a request with a recognised country header arrives. Users seen only through backend apps stay `null` — the country header is dropped at ingest for backend apps because the request originates from a hosting datacenter rather than the end user. See [Events › Country](/docs/concepts/events#country-server-derived).

`last_app_version` is the `app_version` string from the most recent event ingested for this user. It mirrors the `last_country_code` pattern — updated on every batch from the incoming events — and is `null` until an event with a non-empty `app_version` arrives.

`last_sdk_name` and `last_sdk_version` are the SDK identifier and version from the most recent event ingested for this user (e.g. `pubky-pulse-swift` / `0.1.0`). Auto-stamped by official SDKs and updated alongside `last_app_version`. Useful for spotting users on stale SDK versions.

`is_dev` marks the user as a development (test) user vs a real production user. It is derived from the user's **client** events only (apple / android / web apps) on a last-write-wins basis — backend-platform events never set it, because dev/test clients routinely point at production backends. A user is either dev or prod, not both. Filter listings with `data_mode` (`production` is the default).

## GET /v1/app-users

List users across apps/projects/teams. Accepts the same filters as `/v1/apps/:id/users` plus `team_id`, `project_id`, `app_id`, `since`, and `until` for cross-app queries.

**Auth required:** Yes (`apps:read` permission or JWT)

### Query parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `team_id` | string | Filter to a specific team. |
| `project_id` | string | Filter to a specific project. |
| `app_id` | string | Filter to users who have been seen from a specific app. |
| `search` | string | Filter by user_id substring (case-insensitive). |
| `is_anonymous` | string | `"true"` for anonymous users only, `"false"` for identified users only. |
| `data_mode` | string | `production` (default), `development`, or `all`. Filters on the user's `is_dev` flag. |
| `since` | string | Filter by `last_seen_at >= since`. Relative or ISO 8601. |
| `until` | string | Filter by `last_seen_at <= until`. Relative or ISO 8601. |
| `cursor` | string | Cursor from previous response. |
| `limit` | number | Items per page (1-200, default 50). |

Response shape is identical to `/v1/apps/:id/users`. Each user object also carries `last_locale` (the shown locale, e.g. `en_US`) and `last_preferred_language` (the wanted language, e.g. `fr-CA`, null until the user is on the SDK that reports it).

## GET /v1/projects/:projectId/users/locales

Locale demand for a single project — users grouped by wanted language and by country, with the localization gap flagged.

**Auth required:** Yes (`apps:read` permission or JWT)

### Query parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `app_id` | string | Narrow to a single app within the project. |
| `data_mode` | string | `production` (default), `development`, or `all`. Filters on the user's `is_dev` flag. |

### Response

```json
{
  "by_locale": [
    { "locale": "fr-FR", "base_language": "fr", "user_count": 980, "shipped": false }
  ],
  "by_country": [
    { "country_code": "FR", "user_count": 1240 }
  ],
  "supported_languages": ["en", "de"],
  "users_with_preferred_language": 3400,
  "total_users": 5000
}
```

`by_locale` is sorted by `user_count` descending; `locale` is the device's preferred-language tag and `shipped` is `false` when the app doesn't ship that base language (`null` when no `supported_languages` are configured). `by_country` derives from `last_country_code` and is available for every user regardless of SDK version.

## GET /v1/users/locales

Team-scoped variant of the above. `team_id` ⊥ `project_id` ⊥ `app_id`; with no narrowing it aggregates across every project in the caller's teams (and returns `supported_languages: null`, so no gap flags).

**Auth required:** Yes (`apps:read` permission or JWT)

### Query parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `team_id` | string | Filter to a specific team. |
| `project_id` | string | Narrow to a single project (enables gap flags). |
| `app_id` | string | Narrow to a single app (enables gap flags). |
| `data_mode` | string | `production` (default), `development`, or `all`. Filters on the user's `is_dev` flag. |

Response shape is identical to `/v1/projects/:projectId/users/locales`.
