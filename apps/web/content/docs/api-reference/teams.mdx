---
title: Team
description: Read-only endpoints for the single configured team — its record, its roster, and the team audit log.
---

A deployment has exactly one team. Its name, slug and sole owner come from server configuration (`PULSE_DEFAULT_TEAM_NAME`, `PULSE_DEFAULT_TEAM_SLUG`, `PULSE_TEAM_OWNER_EMAIL`) and are established by the startup bootstrap, so **the team is read-only over the API**.

There is no endpoint to create, rename, delete or leave a team, to invite or remove members, or to change a member's role. Those routes no longer exist and return `404`. Roles are `owner` and `member`; there is no `admin`.

What remains is what the product still reads: the team record for `/v1/auth/me`, the roster for the team page and the project-owner picker, and the audit log. Every route pins `:teamId` to the caller's own membership, so a `teamId` that is not the configured singleton team returns `403`.

For who may write what, see [Authentication & Access Control](/docs/concepts/authentication). To change a project's owners, see the [Projects API reference](/docs/api-reference/projects#project-owners).

## GET /v1/teams/:teamId

Get the team record with its roster.

**Auth required:** Yes (JWT or agent key; must be a member of this team)

```json
// Response (200)
{
  "id": "uuid",
  "name": "Example Team",
  "slug": "example-team",
  "created_at": "2024-01-01T00:00:00.000Z",
  "updated_at": "2024-01-01T00:00:00.000Z",
  "members": [
    {
      "user_id": "uuid",
      "email": "owner@example.com",
      "name": "Owner",
      "role": "owner",
      "joined_at": "2024-01-01T00:00:00.000Z"
    },
    {
      "user_id": "uuid",
      "email": "member@example.com",
      "name": "Member",
      "role": "member",
      "joined_at": "2024-01-02T00:00:00.000Z"
    }
  ]
}
```

Returns `403` for a team the caller does not belong to, `404` if the team row is missing.

## GET /v1/teams/:teamId/members

List the roster on its own. Readable by every team member — the roster is what populates the add-owner picker on a project.

**Auth required:** Yes (JWT or agent key; must be a member of this team)

```json
// Response (200)
{
  "members": [
    {
      "user_id": "uuid",
      "email": "member@example.com",
      "name": "Member",
      "role": "member",
      "joined_at": "2024-01-01T00:00:00.000Z"
    }
  ]
}
```

Only name, email, role and join date are exposed. No credential, preference or activity field is included.

## GET /v1/teams/:teamId/members/:userId/agent-keys

List **your own** agent keys for this team, with their secrets. Used by the dashboard's MCP setup flow.

**Auth required:** Yes (JWT only, and `:userId` must be the authenticated user)

Any other `:userId` returns `403`, including for the team owner. An agent key carries its creator's full project access, so handing one to a colleague would hand over that person's authority. Team-wide key *metadata* lives on [`GET /v1/auth/keys`](/docs/api-reference/authentication#get-v1authkeys), where secrets outside the caller's entitlement serialize as `null`.

```json
// Response (200)
{
  "keys": [
    {
      "id": "uuid",
      "name": "Agent Key",
      "secret": "pulse_agent_...",
      "permissions": ["events:read", "apps:read", "..."],
      "created_at": "2024-01-01T00:00:00.000Z"
    }
  ]
}
```

## GET /v1/teams/:teamId/audit-logs

Query the audit log for the team. Returns a paginated list of actions performed on team resources.

**Auth required:** Yes (team owner only). An agent key may read it only when its creator is the team owner *and* the key holds `audit_logs:read`. Everyone else receives `403`.

The team-wide trail spans every project and names who did what, so it is an oversight and recovery surface rather than a colleague-visible one.

### Query parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `resource_type` | string | Filter by resource type: `app`, `project`, `project_owner`, `api_key`, `team`, `team_member`, `metric_definition`, `funnel_definition`, `user`, `job_run`, `issue`, `feedback`, `questionnaire`, `questionnaire_response`. |
| `resource_id` | string | Filter by resource ID. |
| `actor_id` | string | Filter by actor (user or API key) ID. |
| `action` | string | Filter by action: `create`, `update`, `delete`. |
| `since` | string | Start time. Relative (`1h`, `30m`, `7d`, `1w`, `30s`) or ISO 8601. |
| `until` | string | End time. Relative (`1h`, `30m`, `7d`, `1w`, `30s`) or ISO 8601. |
| `cursor` | string | Cursor from previous response (format: `timestamp|id`). |
| `limit` | number | Items per page (1-200, default 50). |

### Response

```json
{
  "audit_logs": [
    {
      "id": "uuid",
      "team_id": "uuid",
      "actor_type": "user",
      "actor_id": "uuid",
      "action": "create",
      "resource_type": "project_owner",
      "resource_id": "uuid",
      "changes": null,
      "metadata": {
        "project_id": "uuid"
      },
      "timestamp": "2024-01-15T10:30:00.000Z"
    }
  ],
  "cursor": "2024-01-15T10:29:00.000Z|uuid",
  "has_more": true
}
```

| Field | Type | Description |
|-------|------|-------------|
| `actor_type` | string | `user`, `api_key`, or `system`. |
| `actor_id` | string | ID of the user or API key that performed the action. |
| `action` | string | `create`, `update`, or `delete`. |
| `resource_type` | string | Type of resource affected. |
| `resource_id` | string | ID of the affected resource. |
| `changes` | object or null | For `update` actions, contains `{ field: { before, after } }` diffs. |
| `metadata` | object or null | Additional context about the action. |

Adding or removing a project owner is recorded as a `project_owner` `create`/`delete` entry whose `resource_id` is the affected user and whose `metadata.project_id` names the project. No secret material is ever written to the trail.
