## Access

Reads span every project in the configured team. A **write** additionally requires the human who created this agent key to currently own the target project — re-read on every request, so an ownership change takes effect on the next call with no key re-issued. A refusal is `403 Requires project ownership`. See [Setup](/docs/mcp/setup#access-model-read-wide-write-narrow).

Creating and updating an app needs ownership of its **parent project**. There is no `delete-app` tool — deleting an app is human-only.

## list-apps

List every app in the team. Reads are team-wide, not limited to the projects this key's creator owns.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `team_id` | UUID | No | Filter by team ID |

Returns `{ apps: [...] }` with each app's `id`, `name`, `platform`, `bundle_id`, `allowed_origins`, `client_secret`, `project_id`, and timestamps. `allowed_origins` is always an array and is empty for everything but a configured `web` app. `client_secret` is `null` for an app whose project this key's creator does not own. Each app also carries `latest_app_version` and `latest_app_version_updated_at` — compare these against an event's `app_version` to tell whether the data is from the current release. See [Latest Version Detection](/docs/concepts/latest-version-detection).

## get-app

Get an app by ID, including its `client_secret` for SDK configuration — `null` unless this key's creator owns the app's project.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `app_id` | UUID | Yes | The app ID |

## create-app

Create a new app under a project. Returns a `client_secret` for SDK use. Requires `apps:write` permission.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `name` | string | Yes | App name |
| `platform` | string | Yes | `apple`, `android`, `web`, or `backend` |
| `project_id` | UUID | Yes | Parent project ID |
| `bundle_id` | string | Conditional | Required for non-backend platforms. Immutable after creation. Reverse-DNS on `apple`/`android`, the site identifier on `web`. |
| `allowed_origins` | string[] | No | `web` only. Browser origins this site may send from. |

```json
{
  "name": "iOS App",
  "platform": "apple",
  "project_id": "550e8400-...",
  "bundle_id": "com.example.myapp"
}
```

Backend apps omit `bundle_id`:

```json
{
  "name": "API Server",
  "platform": "backend",
  "project_id": "550e8400-..."
}
```

A web app's `bundle_id` is the site identifier, and its origins go on the app:

```json
{
  "name": "Acme Web",
  "platform": "web",
  "project_id": "550e8400-...",
  "bundle_id": "app.acme.com",
  "allowed_origins": ["https://app.acme.com", "http://localhost:5173"]
}
```

Create the app with the origins already in place. A web app whose list is empty refuses every request carrying an `Origin` header — which is every request a browser makes — so include the developer's local port alongside the production host. Sending the field for a non-web platform is a `400`.

## update-app

Update an app's `name`, its `allowed_origins`, or both. At least one is required. Requires `apps:write` permission.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `app_id` | UUID | Yes | The app ID |
| `name` | string | No | New app name |
| `allowed_origins` | string[] | No | `web` only. Replaces the whole list. |

`bundle_id` and `platform` are immutable, and an omitted field is left alone — renaming an app never clears its origins. Because `allowed_origins` replaces the list rather than appending to it, read the current value with [`get-app`](#get-app) first and send it back with the addition:

```json
{
  "app_id": "550e8400-...",
  "allowed_origins": [
    "https://app.acme.com",
    "https://staging.acme.com",
    "http://localhost:5173"
  ]
}
```

Each entry is a full origin — scheme, host, optional port, no path, no trailing slash — lowercased and de-duplicated on write, 50 maximum. See [Allowed Origins](/docs/concepts/projects-and-apps#allowed-origins).

## list-app-users

List users for a specific app. Supports search, filtering, and pagination.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `app_id` | UUID | Yes | The app ID |
| `search` | string | No | Search by user ID |
| `is_anonymous` | string | No | `"true"` or `"false"` to filter by anonymous status |
| `data_mode` | string | No | `production` (default), `development`, or `all`. A user's dev/prod flag is derived from their client (non-backend) events. |
| `cursor` | string | No | Pagination cursor |
| `limit` | number | No | Max results (default 50, max 200) |

## list-user-locales

Locale demand for deciding where to localize next. Returns `by_locale` (users grouped by their **wanted** language with a `shipped` flag), `by_country` (works for every user today), `supported_languages`, and totals.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `team_id` | UUID | No | Filter to a team you belong to |
| `project_id` | UUID | No | Narrow to one project (enables the `shipped`/gap flags) |
| `app_id` | UUID | No | Narrow to one app (enables the `shipped`/gap flags) |
| `data_mode` | string | No | `production` (default), `development`, or `all` |

`team_id` ⊥ `project_id` ⊥ `app_id`. `shipped` is `false` for languages the app doesn't ship yet, `true` when shipped, and `null` (no flag) when more than one app is in scope. The language breakdown fills in as users upgrade to the SDK that reports preferred language — until then, lean on `by_country`.
