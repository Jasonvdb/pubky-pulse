## Access

Reads span every project in the configured team. A **write** additionally requires the human who created this agent key to currently own the target project — re-read on every request, so an ownership change takes effect on the next call with no key re-issued. A refusal is `403 Requires project ownership`. See [Setup](/docs/mcp/setup#access-model-read-wide-write-narrow).

Creating a project is the exception: any team member may do it, and **`create-project` makes this key's creator the new project's first owner**, so the very next call can write to it. There is no `delete-project` tool — deleting a project is human-only.

## list-projects

List every project in the team. Reads are team-wide, not limited to the projects this key's creator owns.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `team_id` | UUID | No | Filter by team ID |

Returns `{ projects: [...] }` with each project's `id`, `name`, `slug`, `color`, `team_id`, timestamps, `owners`, and `access_level`.

`access_level` is `owner` or `viewer` **for the human who created this key**. A `viewer` row reads fine but every ordinary write to it returns `403` — check this field before planning a change.

## get-project

Get a project by ID, including its list of apps, its `owners`, and the `access_level` of this key's creator. Readable for every project in the team.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `project_id` | UUID | Yes | The project ID |

Returns the project object with a nested `apps` array. A nested app's `client_secret` is `null` unless the key's creator owns the project.

## create-project

Create a new project. Requires `projects:write` permission. The human who created this key becomes the project's first owner — the key itself never owns anything — so writes to the new project are authorized from the next call onwards.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `team_id` | UUID | Yes | The team to create the project in |
| `name` | string | Yes | Project name |
| `slug` | string | Yes | URL-friendly slug (lowercase, hyphens) |
| `retention_days_events` | integer | No | Days to retain events (default: 120) |
| `retention_days_metrics` | integer | No | Days to retain metric events (default: 365) |
| `retention_days_funnels` | integer | No | Days to retain funnel events (default: 365) |

A display color is auto-assigned on creation; use `update-project` to override it.

```json
{
  "team_id": "550e8400-...",
  "name": "My App",
  "slug": "my-app",
  "retention_days_events": 90
}
```

## update-project

Update a project's name, color, data retention policies, or attachment storage quotas. Requires `projects:write` permission **and** that this key's creator currently owns the project. A `403 Requires project ownership` means a human has to add them to the project's owner list — no new key is needed.

Changing a project's owner list, like deleting a project, is human-only and has no MCP tool.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `project_id` | UUID | Yes | The project ID |
| `name` | string | No | New project name |
| `color` | string | No | Project color as `#RRGGBB` hex (e.g. `#22c55e`). Auto-assigned on creation; override to customize. |
| `retention_days_events` | integer or null | No | Days to retain events (`null` = reset to default 120) |
| `retention_days_metrics` | integer or null | No | Days to retain metric events (`null` = reset to default 365) |
| `retention_days_funnels` | integer or null | No | Days to retain funnel events (`null` = reset to default 365) |
| `attachment_user_quota_bytes` | integer or null | No | Per-user attachment storage quota in bytes (`null` = reset to default 250 MB) |
| `attachment_project_quota_bytes` | integer or null | No | Project-wide attachment storage quota in bytes (`null` = reset to default 5 GB) |

At least one parameter (besides `project_id`) must be provided.
