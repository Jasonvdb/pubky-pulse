## Prerequisites

You need an **agent API key** (`pulse_agent_*`) to connect. A default agent key is created for you on first sign-in — sign in below to see it pre-filled in all editor configs.

<Callout>
Agent keys get all permissions by default and are scoped to your team. You can also create additional keys from the **API Keys** page in the dashboard. See [Authentication](/docs/concepts/authentication) for details on key types and permissions.
</Callout>

## Endpoint URL

The MCP endpoint is `POST /mcp` on your Pubky Pulse API server, and it exposes all 62 tools.

| Environment | URL |
|-------------|-----|
| Pubky's instance (placeholder — substitute your own host) | `https://api.pulse.pubky.org/mcp` |
| Self-hosted | `https://api.yourdomain.com/mcp` |
| Local development | `http://localhost:4000/mcp` |

## Other MCP Clients

Any MCP-compatible client can connect to Pubky Pulse. The endpoint uses:

- **Server name:** `pubky-pulse` (the dashboard emits `pubky-pulse-local-dev` when it is itself running in development, so a local entry doesn't collide with your production one)
- **Transport:** Streamable HTTP (stateless JSON)
- **URL:** your instance's `/mcp` endpoint — `https://api.pulse.pubky.org/mcp` on Pubky's instance, `https://api.yourdomain.com/mcp` self-hosted, `http://localhost:4000/mcp` in local development
- **Auth:** `Authorization: Bearer pulse_agent_YOUR_KEY_HERE` header (required on POST and GET)
- **Mode:** Stateless JSON — each POST request is independent, no session initialization needed. GET opens an authenticated SSE stream; DELETE returns 405.

## MCP Resources

In addition to the tool surface, the server exposes one MCP resource that clients can read on connection:

| URI | Description |
|-----|-------------|
| `pubky-pulse://guide` | Operational guide — concepts, resource hierarchy, workflows, and conventions |

Supported clients read the guide automatically so agents understand how to use the tools effectively. The full SDK and platform documentation lives at [/docs](/docs).

## Authentication

The MCP endpoint only accepts agent API keys (`pulse_agent_*`). Client keys (`pulse_client_*`) and JWT tokens are rejected with 401.

Permissions are enforced per-tool — if your agent key doesn't have `projects:write`, the `create-project` tool will return an error. See [Authentication](/docs/concepts/authentication) for details on API key permissions.

## Verifying the connection

After setup, ask the agent to call the `whoami` tool. It should return your key type, team, and permissions:

```json
{
  "type": "api_key",
  "key_type": "agent",
  "team": { "id": "...", "name": "My Team", "slug": "my-team" },
  "permissions": ["events:read", "projects:read", "apps:read", "..."]
}
```

If you see an authentication error, check that:
1. The key starts with `pulse_agent_` (not `pulse_client_`)
2. The key hasn't expired
3. The URL points to the correct server
