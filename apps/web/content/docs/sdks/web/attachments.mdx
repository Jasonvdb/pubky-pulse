## Attaching a File

The per-call `options` argument of every log method accepts an `attachments` array:

```typescript
Pulse.error(err, "import failed", { rows: "1200" }, {
  attachments: [{ data: file, filename: "import.csv", contentType: "text/csv" }],
});
```

Each entry has these fields:

| Field | Type | Description |
|---|---|---|
| `data` | `Blob \| Uint8Array` | The bytes. A `File` from an `<input type="file">` is a `Blob`, so it can be passed directly. |
| `filename` | `string` | Optional. Filename shown in the dashboard. |
| `contentType` | `string` | Optional. Overrides the type inferred from the data. |

## How the Upload Runs

The event goes out on its normal batch; hashing and upload run on a separate serial queue. Accepted
`Uint8Array` bytes are copied synchronously at enqueue, so later mutation cannot change an upload and
a small subarray does not retain a large backing buffer. Metadata is also snapshotted. Blob sizes are
checked before reading, and the upload still uses the original Blob as its request body.

## Browser Resource Limits

The hardening release intentionally reduces the browser's previous **2 GiB** per-file ceiling to
**5 MiB**. Use a smaller diagnostic file when migrating an existing integration. These limits apply
to the Web SDK; server quotas, attachment wire formats and the other SDKs' limits are unchanged.

| Limit | Behavior |
|---|---|
| 5 MiB per file | Larger files are dropped before reading or hashing. |
| 20 files / 20 MiB combined active and pending payload | New excess files are dropped; budgets are shared across uploader instances in one loaded SDK module. |
| First 20 entries per enqueue | Later entries are not inspected. |
| Filename: 1,024 UTF-16 code units; content type: 255 | Longer metadata is rejected without truncation. |
| 120 seconds per background item and per attachment flush wait | Waiting ends even if a host operation ignores cancellation; PUT requests have an 80-second ceiling. |

`Pulse.flush()` and `Pulse.shutdown()` wait within the attachment deadline. A noncancelable Blob read,
hash or request can outlive that wait; its reservation stays occupied until the underlying work
settles, including across disable/reinitialization. Stop discards pending files and aborts requests;
canceled files cannot start later upload stages. Remaining accepted background work can continue
after a flush returns. The payload budget is not a total browser heap limit: hashing and browser
operations need additional working memory.

## Secure Context Required

Uploads need `crypto.subtle`, which browsers only expose in a secure context (HTTPS or `localhost`). Over plain HTTP the upload is skipped with a debug note and the event is still sent — so an attachment never costs you the error report it was attached to.

## Use Them Sparingly

Each project has a default 5 GB storage quota with a 250 MB per-user bucket. Attach the failed input or the diagnostic bundle that makes an error reproducible, not every request body. See [Attachments](/docs/concepts/attachments) for quotas and for viewing attached files from the dashboard or MCP.

Remember that whatever you attach leaves the user's browser: do not attach anything you would not want stored in your Pulse database.
