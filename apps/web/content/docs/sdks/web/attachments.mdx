## Attaching a File

The per-call `options` argument of every log method accepts an `attachments` array:

```typescript
Pulse.error(err, "import failed", { rows: "1200" }, {
  attachments: [{ data: file, filename: "import.csv", contentType: "text/csv" }],
});
```

Each entry has these fields:

| Field | Type | Description |
|---|---|---|
| `data` | `Blob \| Uint8Array` | The bytes. A `File` from an `<input type="file">` is a `Blob`, so it can be passed directly. |
| `filename` | `string` | Optional. Filename shown in the dashboard. |
| `contentType` | `string` | Optional. Overrides the type inferred from the data. |

## How the Upload Runs

The file is hashed and uploaded out of band, so the event itself is never delayed — the event goes out on the normal batch, and the attachment follows on its own queue. `Pulse.flush()` and `Pulse.shutdown()` both wait for that queue.

## Secure Context Required

Uploads need `crypto.subtle`, which browsers only expose in a secure context (HTTPS or `localhost`). Over plain HTTP the upload is skipped with a debug note and the event is still sent — so an attachment never costs you the error report it was attached to.

## Use Them Sparingly

Each project has a default 5 GB storage quota with a 250 MB per-user bucket. Attach the failed input or the diagnostic bundle that makes an error reproducible, not every request body. See [Attachments](/docs/concepts/attachments) for quotas and for viewing attached files from the dashboard or MCP.

Remember that whatever you attach leaves the user's browser: do not attach anything you would not want stored in your Pulse database.
