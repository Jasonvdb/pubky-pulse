`@synonymdev/pubky-pulse-web` is the browser client for Pubky Pulse: events, errors, metrics, funnels, identity, feedback, and questionnaires from any web app, batched and sent to your own Pulse server. It is framework-agnostic TypeScript with no runtime dependencies, no UI, and no framework bindings — you call it from wherever your app already lives.

Events are stamped with `environment: "web"` and `sdk_name: "pubky-pulse-web"`, so browser traffic lands in the same project as your Node.js, Swift, and Android events.

## Features

- **[Events](/docs/sdks/web/events)** — four log levels (`info`, `debug`, `warn`, `error`) with custom attributes. `Pulse.error` is overloaded: pass a string, or pass the error itself and the SDK extracts the type, the stack, and up to five levels of `cause`. Uncaught exceptions and unhandled rejections are captured automatically and tagged `_unhandled`
- **[Screens and route tracking](/docs/sdks/web/screens)** — History API navigations emit `sdk:screen_appeared` / `sdk:screen_disappeared` on their own; `Pulse.trackScreen()` names anything the URL does not describe
- **[Structured metrics](/docs/sdks/web/metrics)** — `Pulse.startOperation()` measures work with a beginning and an end; `Pulse.recordMetric()` records a measurement you already have
- **[Funnels](/docs/sdks/web/funnels)** — `Pulse.step()` emits named step completions for conversion tracking
- **[Identity](/docs/sdks/web/identity)** — an anonymous id per browser, and `Pulse.setUser()` flushes, claims the anonymous history server-side, then switches the id
- **[User properties](/docs/sdks/web/user-properties)** — `Pulse.setUserProperties()` merges custom metadata onto the current user
- **[Feedback](/docs/sdks/web/feedback)** — `Pulse.sendFeedback()` submits free text with optional name and email, and returns a receipt
- **[Questionnaires](/docs/sdks/web/questionnaires)** — fetch a survey by slug, render it yourself, and save drafts or submissions with the pure answer helpers
- **[Attachments](/docs/sdks/web/attachments)** — attach a `Blob`, `File`, or `Uint8Array` to a single event; the upload runs out of band
- **Network tracking** — opt in to an `sdk:network_request` event per `fetch` call, and propagate `X-Pulse-Session-Id` to the origins you control
- **Batching, gzip, and offline queue** — batches flush on an interval or a threshold, bodies are gzipped through `CompressionStream` where available, and anything that does not make it out is parked in `localStorage` and drained on the next page load

## Requirements

- Any evergreen browser (Chrome, Edge, Firefox, Safari); the build targets ES2020
- A Pubky Pulse app with platform `web`, its bundle id, and a client API key (`pulse_client_...`)
- The site's origin listed in the server's `CORS_ORIGINS`

## Quick Start

```typescript
import { Pulse } from "@synonymdev/pubky-pulse-web";

Pulse.configure({
  endpoint: "https://ingest.pulse.pubky.org",
  apiKey: "pulse_client_...",
  bundleId: "com.example.web",
  appVersion: "1.4.0",
});

Pulse.info("signed_up", { plan: "pro" });
```

Configure as early in the page's life as you can. Calls made before `configure()` are ignored — one console note, then silence — so a stray log during startup can never throw.

## Server Setup

1. Create an app with platform `web` and give it a bundle id, either in the [dashboard](/dashboard) or with the `create-app` MCP tool. The bundle id is the same string you pass as `bundleId`.
2. Add the site's origin to the server's `CORS_ORIGINS`, including the port you use in development (`http://localhost:5173`, say). Without it the browser blocks every request.
3. Copy the app's client key. It starts with `pulse_client_`, is public and ingest-scoped — it writes events, feedback, and user data for this one app, and reads questionnaire specs; it cannot read events, metrics, or project data — and is meant to ship in your bundle. Never put an agent key (`pulse_agent_...`) in a browser.
