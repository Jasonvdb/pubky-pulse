With `trackPageViews` on (the default), the SDK patches `pushState` / `replaceState` and listens for `popstate`, tracking `location.pathname` as the screen name by default. Hash-only changes — in-page anchors — are ignored. Use `screenNameForPath` to map routes to stable names without adding your own router observer.

## Mapping Route Names

Dynamic paths can contain user IDs, post IDs, or invite codes. Compile explicit app-owned route
templates into the existing `screenNameForPath` hook:

```typescript
import { createScreenNameMapper, Pulse } from "@synonymdev/pubky-pulse-web";

const screenNameForPath = createScreenNameMapper([
  "/", "/home", "/profile/followers", "/profile/[pubky]", "/invite/[inviteCode]",
], { fallback: "/unknown" });

Pulse.init({ apiKey: "pulse_client_...", screenNameForPath });
```

Reuse safe constants from your app router. The helper emits only a literal configured template or
fallback (default `/unknown`), never captured values. `/profile/followers` takes precedence over
`/profile/[pubky]` regardless of definition order. More static segments win; equally specific
patterns that overlap are rejected. Repeated identical constants are allowed.

Only whole-segment `[name]` placeholders are supported, each matching one nonempty segment.
Optional, catch-all and partial-segment patterns are unsupported. Query/fragment and trailing
slashes are ignored. Segments are decoded once, so `/profile/%66ollowers` matches the static route;
invalid escapes, encoded separators, dot segments, whitespace/control characters, repeated interior
slashes and absolute URLs use the fallback. Invalid template configuration throws during helper
creation. The SDK cannot infer safe routes or fallback labels: these remain app-owned.

The [Pubky App before/after example](https://github.com/Jasonvdb/pubky-pulse-web/blob/main/examples/pubky-app.md)
shows how existing enums and a profile-route generator replace regexes and captured-path logic.
See [Configuration](/docs/sdks/web/configuration) for release availability.

Custom synchronous `screenNameForPath` callbacks remain supported without this helper.
The callback receives only the pathname, without the origin, query string, or hash. It runs for the initial page and History API navigation (`pushState`, `replaceState`, and `popstate`). The mapped name is used for screen events, durations, and the default `screen_name` on subsequent events. Navigating between paths mapped to the same name preserves the current duration and emits no screen transition.

The callback must be synchronous and return a non-blank string; invalid callback types are rejected by `configure()`. If it throws or returns a non-string or blank name, the SDK ends the previous screen, clears the default screen name, and emits no new `sdk:screen_appeared` until a valid mapping or manual screen is recorded. It does not fall back to the raw path. Omitting the option retains the default pathname behavior; with `trackPageViews: false`, the mapper is not used.

Mapping applies only to automatic screen names. It leaves `Pulse.trackScreen()` and per-event `screenName` overrides as supplied. It does not sanitize `_page_url`, `_referrer`, `_http_url`, error stacks, or application attributes; review those separately before recording URLs containing identifiers or tokens.

## What It Emits

| Event | Level | When | Attributes |
|-------|-------|------|------------|
| `sdk:screen_appeared` | debug | A screen becomes visible | `screen_name` set to the new screen |
| `sdk:screen_disappeared` | debug | The previous screen is left | `screen_name` set, `_duration_ms` with the time it was visible |

Both are debug-level, so they are filtered out of the default production view. Switch to development data (or filter by level) to see screen flow when you need it. `sdk:screen_disappeared` carries the duration and is the more useful analytics signal; `sdk:screen_appeared` is retained so you can spot screens that were opened but never left.

## Manual Screens

For anything the URL does not describe — a modal, a wizard step, a tab — name it yourself:

```typescript
Pulse.trackScreen("Checkout / Payment");
```

`trackScreen` also sets the default `screen_name` for the events that follow, until the next screen change. Repeating the current name is a no-op, so calling it on every render is safe.

## Routers Without the History API

Some hash routers never touch `pushState`, so there is nothing for the SDK to observe. Turn the automatic tracking off and drive it from your own route handler:

```typescript
Pulse.init({
  apiKey: "pulse_client_...",
  trackPageViews: false,
});

router.afterEach((to) => {
  Pulse.trackScreen(to.name ?? to.path);
});
```

With `trackPageViews` off, the SDK still keeps a current screen — only `trackScreen()` moves it.

## Overriding a Single Event

To tag one event with a different screen without changing the current one, pass `screenName` in the per-call options:

```typescript
Pulse.info("exported_report", { rows: 940 }, { screenName: "Reports" });
```
