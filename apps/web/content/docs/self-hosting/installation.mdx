Step-by-step guide to installing Pubky Pulse on a fresh Ubuntu 24.04 VPS. Estimated time: 15-20 minutes.

## 1. Run the setup script

SSH into your VPS as root and run the setup script. It installs Node.js 22, PostgreSQL 16, nginx, pm2, pnpm, and creates the database.

```bash
curl -fsSL https://raw.githubusercontent.com/pubky/pubky-pulse/main/deploy/setup-ubuntu-vps.sh -o setup-ubuntu-vps.sh
bash setup-ubuntu-vps.sh
```

Save the `DATABASE_URL` printed at the end. You will need it in step 3.

The script is idempotent and safe to run again if interrupted.

## 2. Clone and build

The setup script creates `/opt/pubky-pulse` as an empty directory. Clone the repo into it:

```bash
cd /opt/pubky-pulse
git clone https://github.com/pubky/pubky-pulse.git .
pnpm install
pnpm build
```

The build compiles all packages in dependency order: `shared` then `db` then `server`, plus the Next.js web dashboard.

<Callout>
On a ~1 GB VPS the Next.js build can run out of heap. If `pnpm build` is killed, raise the heap limit: `NODE_OPTIONS='--max-old-space-size=1024' pnpm build`.
</Callout>

<Callout type="warn">
`pnpm build` bakes `NEXT_PUBLIC_API_URL` into the dashboard's client bundle. Write `apps/web/.env` (step 3) **before** building, or the dashboard will call `http://localhost:4000` from your visitors' browsers and every request will fail. If you have already built, just run `pnpm build` again after writing it.
</Callout>

## 3. Configure environment

```bash
cp .env.example .env
```

Edit `.env` with your values:

```bash
NODE_ENV=production
DATABASE_URL=postgresql://pubky_pulse:<password>@localhost:5432/pubky_pulse
JWT_SECRET=<random-64-char-string>
PORT=4000
HOST=0.0.0.0
CORS_ORIGINS=https://yourdomain.com
WEB_APP_URL=https://yourdomain.com
API_PUBLIC_URL=https://api.yourdomain.com
COOKIE_DOMAIN=.yourdomain.com
MAX_DATABASE_SIZE_GB=8

# Identity — REQUIRED, no defaults. The server refuses to start without all four.
PULSE_ALLOWED_EMAIL_DOMAINS=yourdomain.com
PULSE_DEFAULT_TEAM_NAME=Your Team
PULSE_DEFAULT_TEAM_SLUG=your-team
PULSE_TEAM_OWNER_EMAIL=you@yourdomain.com

RESEND_API_KEY=<your-resend-key>
EMAIL_FROM=noreply@yourdomain.com

# Event attachments (required in production — server refuses to start without the signing secret)
PULSE_ATTACHMENTS_PATH=/opt/pubky-pulse-attachments
PULSE_ATTACHMENTS_SIGNING_SECRET=<random-hex-string, must differ from JWT_SECRET>
PULSE_ATTACHMENTS_INTERNAL_URI=/_attachments/
```

The dashboard reads its own env file — Next.js resolves `.env` relative to `apps/web`, not the repo root — so write that one too:

```bash
echo 'NEXT_PUBLIC_API_URL=https://api.yourdomain.com' > apps/web/.env
```

That is the API base URL as reached from the *browser*. It is inlined at build time, so re-run `pnpm build` if you change it later.

The four `PULSE_*` identity variables decide who can use the instance at all. Only addresses on `PULSE_ALLOWED_EMAIL_DOMAINS` can sign in; matching is exact, so list a subdomain separately if you want it. Every allowed person joins the one team named by `PULSE_DEFAULT_TEAM_NAME`/`PULSE_DEFAULT_TEAM_SLUG`, and `PULSE_TEAM_OWNER_EMAIL` — whose domain must be in the allowlist — is its sole owner. See [Authentication & Access Control](/docs/concepts/authentication).

Point them at a **fresh database**. On startup the server creates or adopts the team with the configured slug and fails if a second active team already exists, so an existing database from an earlier install has to be dealt with first.

Generate the secrets:

```bash
openssl rand -base64 48    # JWT_SECRET
openssl rand -hex 32       # PULSE_ATTACHMENTS_SIGNING_SECRET (must NOT equal JWT_SECRET)
```

Create the attachments directory so the API server can write to it:

```bash
mkdir -p /opt/pubky-pulse-attachments
```

See [Configuration](/docs/self-hosting/configuration) for a full reference of all environment variables.

## 4. Run migrations

Migrations run from `packages/db` and do not auto-load the root `.env`, so prefix the command with `DATABASE_URL`:

```bash
DATABASE_URL='postgresql://pubky_pulse:<password>@localhost:5432/pubky_pulse' pnpm db:migrate
```

This creates all database tables and sets up monthly event partitions. The `events`, `metric_events`, and `funnel_events` tables use `PARTITION BY RANGE` on the `timestamp` column. Partitions for the current month plus the next 2 months are created automatically.

Startup creates the configured team, and creates the configured team owner's user row if it does not exist yet. Other accounts are auto-created on first sign-in, provided the address is on an allowed domain.

## 5. Verify the server starts

Test that the API server runs:

```bash
node apps/server/dist/index.js
```

You should see output indicating the server is listening on port 4000. Press Ctrl+C to stop.

Test the health endpoint:

```bash
curl -s http://localhost:4000/health
# {"status":"ok"}
```

## Development seed data

For development or testing only, you can populate the database with sample data:

```bash
pnpm dev:seed         # Creates a user, team, project (with an owner), app, and API keys
pnpm dev:seed-events  # Generates 200 random test events across 24 hours
```

Do not run the seed commands in production. The seed API keys are committed to the repository and publicly known.

The seed inserts its own team (`Default Team` / `default`, owned by `admin@pulse.pubky.org`). Because the server allows exactly one active team, a seeded database needs the four `PULSE_*` variables pointed at that team and domain, or startup fails on the extra team.
